 Key 按键模块使用说明(KeyRead)
 模块文件: User/Key.c + User/Key.h
 更新日期: 2026-09-09(单击/双击/长按功能已验证可用)
================================================================================

一、功能概述
--------------------------------------------------------------------------------
1. 两个按键的非阻塞扫描模块, 识别三种动作: 单击(OneButton)、双击(TwoButton)、
   长按(LongButton), 另有一个空闲状态 等待(Waiting)。
2. 扫描时基由 TIM2 每 1ms 中断驱动(时基代码在 main.c 的 Timer_Init()),
   按键检测全程无 Delay 阻塞等待, 不会卡住主循环。
3. 自带软件消抖(10ms), 电平翻转需连续稳定 10 个节拍才被确认。
4. 两个按键相互独立: 各自有独立的动作状态变量与内部状态机。

二、硬件连接与引脚
--------------------------------------------------------------------------------
Key1 = PB1, Key2 = PB11
 - GPIO 模式: 下拉输入(GPIO_Mode_IPD), 即引脚默认被内部电阻拉低;
 - 按键另一端接 3.3V(高电平), 按下时引脚变为高电平, 松开恢复低电平;
 - 注意: 若按键接的是 GND(上拉接法), 本模块将无法检测到按下,
   需将按键改为接 3.3V 或把 Key.c 中 GPIO_Mode_IPD 改回 GPIO_Mode_IPU
   并同步反转 KEY_PRESSED/KEY_RELEASED 的电平定义。

三、四个动作状态(枚举, 定义在 Key.h)
--------------------------------------------------------------------------------
   Waiting     = 0   等待: 空闲无动作(上电初始/Key_Clear 后的状态)
   OneButton   = 1   单击: 短按一次
   TwoButton   = 2   双击: 0.3s 内连续按两次
   LongButton  = 3   长按: 按下持续 0.6s 以上

   KeyAction1  : Key1(PB1)  的动作状态, 全局变量, extern 声明在 Key.h
   KeyAction2  : Key2(PB11) 的动作状态, 全局变量, extern 声明在 Key.h
   主程序直接读取这两个变量即可知道动作, 例如:
       if (KeyAction1 == OneButton) { /* Key1 被单击 */ }

四、对外接口函数
--------------------------------------------------------------------------------
1) void Key_Init(void)
   功能: 按键 GPIO 初始化(使能 GPIOB 时钟, PB1/PB11 配置为下拉输入),
         复位两个按键的内部状态机, 并把 KeyAction1/KeyAction2 清为 Waiting。
   注意: 本函数不再配置定时器, 1ms 时基需另行调用 main.c 中的 Timer_Init()。

2) void Key_Clear(void)
   功能: 把 KeyAction1 / KeyAction2 全部清回 Waiting。
   用法: 主循环里读出动作并处理完后调用一次;
   警告: 动作尚未被清除期间, 模块产生的新动作会被"丢弃"(不覆盖写入),
         以保证已经上报的动作不会被悄悄顶掉——因此要尽快处理并清除,
         否则快速操作可能丢动作。

3) void Key_Tick(void)
   功能: 1ms 节拍扫描函数, 内部依次对 Key1、Key2 执行一次完整扫描
         (消抖 + 沿检测 + 状态机计时)。
   调用: 由 main.c 中 TIM2_IRQHandler 每 1ms 调用一次;
         若自行更换时基, 必须保证按 1ms 周期调用本函数,
         否则所有时间参数(消抖/窗口/长按)都会按比例失真。

五、时基来源(main.c, 参考工程已验证写法)
--------------------------------------------------------------------------------
   Timer_Init(): 使用 TIM2
     - 内部时钟 TIM_InternalClockConfig(TIM2)
     - 预分频 PSC = 720-1, 自动重装 ARR = 100-1
       (前提: 系统时钟 72MHz => 计数频率 100kHz, 每 100 次溢出 = 1ms)
     - TIM_TimeBaseInit 后调用 TIM_ClearFlag 清除初始更新标志,
       避免开中断后立刻多进一次中断
     - TIM_ITConfig 开启更新中断
     - NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2)
     - TIM2_IRQn: 抢占优先级 2, 响应优先级 1
     - 最后 TIM_Cmd(TIM2, ENABLE) 启动

   TIM2_IRQHandler(): 中断服务函数, 位于 main.c
     if (TIM_GetITStatus(TIM2, TIM_IT_Update) == SET)
     {
         TIM_ClearITPendingBit(TIM2, TIM_IT_Update);
         Key_Tick();   // 每 1ms 驱动一次按键扫描
     }

六、动作识别时序(核心判定逻辑, 状态机在 Key_Scan 中)
--------------------------------------------------------------------------------
时间参数宏(位于 Key.c 顶部, 可按需修改):
   KEY_DEBOUNCE_MS   10    消抖时间(ms)
   KEY_DOUBLE_WIN_MS 300   双击判定窗口(ms)
   KEY_LONG_MS       600   长按阈值(ms)

每个按键内部状态字段(Key_Dev_t):
   Level      去抖后的电平(KEY_RELEASED=0 / KEY_PRESSED=1)
   StableCnt  电平稳定计数(连续多少个节拍同电平, 用于消抖)
   Phase      内部阶段: P_IDLE / P_PRESS / P_WAIT2 / P_2NDPRESS
   LongDone   本次按下是否已上报过长按(防止重复上报/松开误判)
   PressMs    本次按下已持续毫秒数(长按计时)
   WaitMs     双击窗口剩余毫秒数(倒计时)

单键工作流程(以 Key1 为例, Key2 完全对称):
   1) 空闲 P_IDLE: 等待按下。
   2) 按下消抖: 引脚连续 10ms 为高(KEY_PRESSED)后, 确认"按下沿",
      进入 P_PRESS, 开始累计 PressMs(每节拍+1)。
   3) 若 PressMs 达到 600(KEY_LONG_MS)且未上报过长按:
      上报 LongButton(长按), LongDone=1; 之后继续按住不会再上报。
      长按后松开: 直接回 P_IDLE, 不再产生单击/双击。
   4) 短按松开(未到长按阈值): 确认"松开沿"后进入 P_WAIT2,
      开启 300ms 倒计时(WaitMs=300), 此时不产生任何上报
      —— 这正是"双击不会短闪 1"的关键: 单击要等窗口结束才定论。
   5) P_WAIT2 期间(300ms 窗口内)再次按下:
      立即上报 TwoButton(双击), 进入 P_2NDPRESS;
      第二次松开后回到 P_IDLE。
   6) P_WAIT2 倒计时结束仍无第二次按下:
      上报 OneButton(单击), 回到 P_IDLE。

上报与清除机制:
   Key_Report(): 只有当对应动作状态仍为 Waiting 时才写入新动作
   (防止覆盖尚未被主程序处理的动作)。
   因此用户时序为: 查询 KeyAction1/2 -> 处理 -> Key_Clear() -> 回到查询。

七、main.c 使用示例(当前工程实测布局)
--------------------------------------------------------------------------------
   OLED 第 1 行: KeyAction1 的值(0~3)与名称(Wait/One/Two/Long)
   OLED 第 2 行: KeyAction2 的值与名称
   OLED 第 3 行: 图例 "0:Wait 1:One"
   OLED 第 4 行: 图例 "2:Two  3:Long"
   显示行为: 动作值保持显示直到下一次动作(便于肉眼观察);
   仅在出现动作时才刷新 OLED, 平时主循环空转不占用 I2C。

   main 中初始化顺序:
       OLED_Init();      // OLED(PB8/PB9 软件I2C)
       Key_Init();       // 按键 GPIO(下拉输入)
       Timer_Init();     // TIM2 1ms 时基(中断里自动调 Key_Tick)

   主循环核心逻辑:
       while (1)
       {
           if (KeyAction1 != Waiting) { 记录并显示; }
           if (KeyAction2 != Waiting) { 记录并显示; }
           Key_Clear();                 // 处理完毕统一清除
           if (有动作) { 刷新OLED; }
       }

八、验证情况
--------------------------------------------------------------------------------
 - 在 STM32F103C8 实测: 单击(松开后约0.3s显示1)、双击(不闪1直接显示2)、
   长按(0.6s显示3)均正常; 按键为下拉输入接 3.3V 接法。
 - 逻辑仿真场景均通过: 慢速单击、快速连按(间隔>300ms 各自判单击)、
   双击、长按、长按后再单击、按下/松开抖动、短毛刺忽略等。

九、注意事项
--------------------------------------------------------------------------------
 1. 双击窗口存在期间单击结果要等 300ms 才产生, 属正常设计(区分双击的代价)。
 2. 两次按键间隔小于 300ms 会被判为双击, 快速单击请放慢到 300ms 以上。
 3. 若某个动作已上报但未 Key_Clear, 期间的新动作会被丢弃。
 4. 移植到其他工程时: 拷贝 User/Key.c、User/Key.h, 并在 main.c 中
    实现 Timer_Init(TIM2) 与 TIM2_IRQHandler(每 1ms 调 Key_Tick)。
